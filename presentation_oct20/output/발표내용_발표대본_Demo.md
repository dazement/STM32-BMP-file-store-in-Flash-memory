# 2차 발표: UART 및 SPI Flash 기본 기능 구현

발표일: 2026년 10월 21일

## 발표에서 전달할 핵심

PC에서 보낸 3,145,782바이트 BMP 전체를 SPI Flash에 저장하고,
Flash에서 다시 읽어 PC에 복원했습니다. 원본과 복원 파일은 바이트 단위로 일치하며,
CRC32와 SHA-256도 같습니다.

필수 Demo에서는 원본 파일을 그대로 복원합니다. 입력과 복원 파일은 모두
24비트 True Color BMP입니다. UART 전송 단위는 이미 8비트, 통신 설정은 8N1입니다.
추가 기능인 회색조 변환 결과는 8비트 BMP로 고정했습니다.

**실제 칩 조건:** 기존 실물 확인 기록은 W25Q128, JEDEC EF4018, 16 MiB입니다.
과제의 W25Q32는 JEDEC EF4016, 4 MiB입니다. 현재 코드는 이미지 영역을 첫 4 MiB 안으로
제한하고 두 ID를 지원하지만, W25Q32 실물을 사용했다는 의미는 아닙니다.
실물 W25Q32가 필수인지, 현재 내장 Flash 대체를 인정하는지 담당 교수에게 확인해야 합니다.

## 슬라이드별 내용과 발표 대본

### 1. UART 및 SPI Flash 기본 기능 구현

내용: 발표 주제, 보드, 발표일

대본: “이번 발표에서는 STM32F746을 이용해 PC에서 보낸 대용량 BMP를
SPI Flash에 저장하고 다시 PC로 복원하는 기능을 설명하겠습니다.
최종 확인은 원본과 복원 파일 전체의 데이터가 같은지 비교하는 방식으로 진행했습니다.”

### 2. 이번 Demo의 확인 항목

내용: UART 연결, SPI 연결, Flash 삭제·쓰기·읽기, 3 MiB 이상 전송, 무결성 검사

대본: “PC와 MCU는 UART로 통신하고, MCU와 Flash는 SPI 방식으로 통신합니다.
파일 헤더와 픽셀, 행 패딩까지 포함한 전체 파일을 저장합니다.
저장 완료 후 Flash 데이터를 다시 읽어 PC 파일로 복원합니다.”

### 3. 실제 하드웨어와 과제 조건

내용: STM32F746G-DISCO, 실제 W25Q128과 요구 W25Q32의 차이, 논리 영역 제한

대본: “현재 보드의 내장 외부 Flash를 사용했습니다. 기존 JEDEC 확인 기록은 EF4018로,
W25Q128 계열의 16 MiB 칩입니다. 과제에서 지정한 W25Q32는 4 MiB입니다.
현재 구현은 4 MiB 안의 이미지 영역을 사용하지만, 칩 대체 조건은 별도로 확인해야 합니다.”

### 4. UART 8N1과 Double Buffer

내용: USART1 PA9/PB7, 921600 baud 실측 조건, 4 KiB 수신 버퍼 두 개,
하드웨어 DBM, DMA 송신, 청크 CRC와 ACK

대본: “UART는 데이터 8비트, 패리티 없음, 정지 비트 1개로 설정했습니다.
수신 DMA는 두 개의 4 KiB 버퍼를 번갈아 채웁니다.
PC는 최대 두 청크를 미리 보내므로 Flash에 한 청크를 기록하는 동안 다음 청크를 수신할 수 있습니다.
송신도 DMA 버퍼 두 개를 사용해 Flash 읽기와 UART 전송이 겹치도록 구성했습니다.”

### 5. SPI Flash Read / Write

내용: QUADSPI 주변장치를 이용한 일반 SPI 1-1-1 방식, Mode 0, 27 MHz,
JEDEC/Write Enable/Status/Block Erase/Page Program/Read 명령

대본: “보드 내장 Flash의 배선은 QUADSPI 주변장치에 연결되어 있습니다.
현재 명령과 주소, 데이터를 각각 한 선으로 보내는 일반 SPI 방식으로 사용합니다.
쓰기 전에 Write Enable을 수행하고, 상태 레지스터의 BUSY 비트가 해제되는지 확인합니다.
256바이트 페이지 경계를 넘지 않게 기록합니다.”

### 6. 대용량 이미지 저장 구조

내용: 입력 크기, 주소 영역, 64 KiB 블록 삭제, 256바이트 페이지 쓰기, 청크 읽기

대본: “테스트 입력은 1024 곱하기 1024 크기의 24비트 BMP로, 전체 크기는
3,145,782바이트입니다. 64 KiB 단위로 필요한 영역을 삭제하고 256바이트 단위로 기록합니다.
이 파일은 49개 블록 삭제 범위와 12,289개 페이지 기록에 해당합니다.
MCU는 전체 이미지를 RAM에 보관하지 않고 작은 버퍼를 재사용합니다.”

### 7. 원본과 Flash 재읽기 파일이 일치

내용: 원본과 복원 이미지, 파일 크기, CRC32, SHA-256 및 바이트 비교 결과

대본: “복원 파일도 원본과 같은 3,145,782바이트입니다.
두 파일의 CRC32는 모두 978AB7D9이며 SHA-256도 같습니다.
실제로 전체 바이트를 직접 비교해 일치 여부를 확인했습니다.
이미지를 열어 정상 표시되는지도 확인합니다.”

### 8. 현장 Demo 실행 순서

내용: 원본 확인, 새 펌웨어 실행, Demo 명령, PASS 및 복원 BMP 확인,
리셋 후 읽기 확인

대본: “먼저 원본 BMP의 크기와 화면을 보여드리겠습니다.
그다음 프로그램이 파일 전체를 Flash에 기록하고 다시 읽어 복원합니다.
마지막으로 PASS 메시지와 무결성 값을 확인하고 복원 이미지를 열겠습니다.
추가로 MCU를 리셋한 뒤 저장된 Flash만 읽어 같은 결과가 나오는지 확인할 수 있습니다.”

### 9. 확인된 결과와 남은 조건

발표 직전 최신 펌웨어로 다시 실행한 기록을 보여드리겠습니다.
W25Q32 실물 사용 조건은 현재 내장 W25Q128 사용과 구분해 설명하겠습니다.”

## 질문에 대한 답변

**왜 UART 8비트와 BMP 8비트를 구분하나요?**
UART 8N1은 한 프레임의 데이터 비트 수입니다. 24비트 BMP의 픽셀도
B, G, R 각각의 8비트 바이트로 나누어 전송합니다.
8비트 Gray BMP는 픽셀당 한 바이트를 사용하므로 출력 파일 크기를 줄입니다.
원본을 그대로 복원할 때에는 입력 파일의 픽셀 형식을 유지합니다.

**왜 Quad-SPI라고 표시되는데 SPI라고 설명하나요?**
QUADSPI는 사용한 MCU 주변장치의 이름입니다. 현재 프로토콜은 명령, 주소, 데이터가
각각 1선인 SPI 1-1-1입니다. 4선 데이터 전송은 현재 사용하지 않습니다.

**Flash에 실제로 저장했음을 어떻게 확인하나요?**
쓰기 후 해당 주소를 Flash 명령으로 다시 읽고 입력 청크와 비교합니다.
전체 파일을 별도로 다시 읽어 PC에 복원합니다.
리셋 후 읽기 전용 Demo까지 수행하면 MCU RAM 데이터에 의존하지 않는 것을 보여줄 수 있습니다.

**CRC만 같으면 충분한가요?**
전송 중에는 CRC32를 사용하고 최종 복원에서는 SHA-256 및 전체 바이트 비교도 수행합니다.
이미지 화면 확인은 파일이 정상적으로 열리는지 확인하는 추가 절차입니다.

**3 MB가 정확히 어떤 기준인가요?**
입력은 3,145,782바이트로, 3,000,000바이트와 3 MiB인 3,145,728바이트를 모두 초과합니다.

**실제 W25Q32인가요?**
기존 보드 확인 기록은 W25Q128입니다. 코드가 W25Q32의 ID와 용량 조건을 지원해도
실제 W25Q32를 시험했다는 의미는 아닙니다. 담당자의 대체 허용 또는 외부 칩 시험이 필요합니다.

## 현재 확인한 증거와 측정 범위

자료 작성 시 원본과 기존 복원 BMP를 다시 비교했고 완전히 일치했습니다.
이는 기존 실물 출력 파일의 검증입니다. 이번 코드 변경 이후의 새 실물 Demo는
`demo_roundtrip.py` 실행 결과로 추가 확인해야 합니다.

Gray 비교값은 `pc/results/timings.csv`의 2026-10-13 기록입니다.
동일한 3,145,782바이트 입력, 921600 baud에서 각 1회 측정했습니다.
백업 준비 시간은 별도이며, 삭제·저장·Flash CRC 검사·변환·Gray 전송 시간은 본 구간에 포함합니다.
새로운 송신 DMA 적용 및 8비트 고정 이후의 시간이 이전 값과 동일하다고 가정하지 않습니다.
